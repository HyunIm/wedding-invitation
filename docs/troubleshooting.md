# 문제가 생겼을 때

Actions에서 **가장 최근에 실행한 ‘청첩장 배포’**를 열어 어느 단계가 실패했는지 확인하세요. 빨간 ❌가 항상 config.js 문법 오류라는 뜻은 아닙니다. 저장소 생성 직후의 옛 실패보다 이번 실행 결과가 중요합니다.

| 실패한 단계/상황 | 해결 |
|---|---|
| GitHub Pages 설정 확인 | Settings → Pages → Source를 GitHub Actions로 설정하고 Actions → 청첩장 배포 → Run workflow 실행 |
| config.js 검사 및 빌드 | 오류에 나온 항목을 확인. 실제 날짜/시간, 이름/장소, 표지 사진, 자료형과 공개 범위 확인 필요 |
| 회귀 테스트 | 변경한 파일과 실패한 테스트 로그를 AI에게 전달. 내용을 추측해 지우지 않기 |
| 사진 용량 줄이기 / 설치 | 해당 단계의 오류 확인. 깨진 파일은 사진 앱에서 다시 내보내기. 외부 서비스의 일시 장애라면 재실행 |
| 배포 | 저장소 Pages 권한·환경 설정·Actions 로그 확인. config.js를 무작정 다시 쓰지 않기 |
| Actions 자체가 실행 안 됨 | Actions 탭에서 실행 허용 여부 확인, main 브랜치에 저장했는지 확인 |

오류를 AI에 보낼 때는 **실패 단계 이름, 오류 문구, 최신 설정 파일**을 함께 보내세요. 토큰·비밀번호·인증번호는 보내지 마세요. 이름이나 계좌 등 필요 없는 개인정보는 지워도 됩니다.

## 처음 만든 저장소가 실패해요

새 config.js는 의도적으로 이름·날짜·장소가 비어 있고 공개 확인도 꺼져 있습니다. README 순서대로 필수 정보와 사진을 준비한 뒤 Pages를 켜고 수동 실행하세요. 제작자 데모 데이터는 새 저장소에 자동 적용되지 않습니다.

## ✅인데 내용이 잘못됐어요

검사는 정해진 규칙을 확인할 뿐 이름·계좌의 실제 소유자나 예식 정보를 확인하지 못합니다. 실수한 값을 수정하고 다시 저장하세요. 이번 배포가 완료된 뒤 새로고침하세요. 카톡 미리보기만 예전 내용이라면 [공유 캐시 안내](kakao-share.md)를 보세요.

## 사진이 없어요

표지는 images/cover.jpg, 갤러리는 images/gallery 폴더 안에 있는지 확인하세요. ZIP은 압축을 풀어서 사진만 올립니다. HEIC를 JPG로 이름만 바꾸지 말고 실제로 내보내기 하세요. 필수 표지 누락은 배포를 막고 선택 사진 누락은 경고합니다.

## 지도 위치가 달라요

좌표가 없으면 주소로 검색합니다. 결과에서 예식장을 직접 확인하세요. 정확한 좌표를 알고 있으면 wedding.lat/lng를 숫자로 함께 입력하세요. 위도 -90~90, 경도 -180~180 범위이며 두 값 중 하나만 넣으면 배포가 중단됩니다.

## 방명록/참석 여부가 안 나와요

googleScriptUrl이 비어 있으면 숨겨집니다. [구글 시트 설정](guestbook-rsvp.md)을 완료하세요. ‘너무 자주 보냈어요’는 1분 후 다시 시도하세요. 네트워크 오류 후 같은 창에서 재시도하면 짧은 시간 동안 중복 저장을 피하도록 처리합니다.

## 비공개로 만들고 싶어요

이 템플릿의 무료 배포 안내는 공개 저장소 기준입니다. 화면에서 숨기거나 Pages를 끄더라도 공개 저장소 파일과 이력이 비공개로 바뀌지는 않습니다. 비공개가 필요하면 공개를 멈추고 별도 접근 제어를 지원하는 서비스를 검토하세요.

## 결혼식 이후

Pages를 끄면 사이트는 내려가지만 공개 저장소의 파일은 남습니다. 사진·설정과 Git 이력, 구글 시트 응답은 각각 관리해야 합니다. 기록 정리와 저장소 삭제는 복구에 영향을 주므로 필요한 자료를 먼저 보관하세요.
