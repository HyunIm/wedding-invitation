# 사진과 음악 준비

**공개할 사본만 업로드하세요.** 저장소는 Public입니다. 배포용 최적화는 저장소 원본의 위치정보를 없애지 않습니다.

## 업로드 전 사진 정리

1. [사진 준비 도구](https://hyunim.github.io/wedding-invitation/prepare.html)를 열고 용도를 선택하세요.
2. 사진을 선택한 뒤 **사진 정리하기**를 누르세요. 브라우저에서 JPG 사본으로 다시 만들며, 위치·기기 정보를 복사하지 않습니다. 서버 전송도 하지 않습니다.
3. 미리보기를 확인하고 ZIP을 내려받아 압축을 푸세요. 실패한 사진은 파일 이름과 원인을 보여줍니다. 실패 파일은 ZIP에 포함되지 않아요.
4. ZIP 안의 폴더 구조에 맞춰 **사진 파일**을 올리세요. ZIP 자체를 업로드하지 마세요.

| 업로드 위치 | 용도 |
|---|---|
| images/cover.jpg | 표지, 필수. 세로 구도 권장 |
| images/og.jpg | 공유 미리보기, 선택. 가로 1200×630 권장 |
| images/closing.jpg | 마무리, 선택 |
| images/gallery/01.jpg … | 갤러리. 파일 이름 순서로 자동 표시 |

표지 업로드: `https://github.com/내아이디/저장소이름/upload/main/images`
갤러리 업로드: `https://github.com/내아이디/저장소이름/upload/main/images/gallery`

`Add file → Upload files` 또는 위 주소에서 사진을 끌어다 놓고 `Commit changes`를 누르세요. GitHub 웹 업로드는 파일 하나당 25MB까지이며, 준비 도구로 만든 파일은 보통 훨씬 작습니다. 확장자 대소문자는 보정하지만 파일 이름의 `#`, `?`는 피하세요.

## 아이폰 HEIC/HEIF

HEIC/HEIF는 지원하지 않습니다. Mac 사진 앱에서 **파일 → 내보내기**로 JPEG를 선택하거나 미리보기 앱의 **파일 → 내보내기 → JPEG**를 사용하세요. 다른 기기도 사진 앱의 JPEG 내보내기를 이용하세요. 확장자만 `.jpg`로 바꾸면 파일 형식은 그대로입니다. 아이폰 카메라의 '높은 호환성' 설정은 이후 촬영할 사진에 적용되며 기존 사진을 바꾸지 않아요.

## 배포 시 최적화

배포본은 최대 1600px로 축소하고 갤러리 썸네일을 만듭니다. 저장소에 올라간 원본은 그대로 남아요. **이미 원본을 올렸다면 삭제 커밋만으로 이전 Git 기록의 원본까지 지워지지는 않습니다.** 민감한 원본은 GitHub의 기록 정리 안내에 따라 별도로 처리해야 합니다. 이 템플릿이 기록을 자동 삭제하지는 않아요.

## 음악과 약도

공개할 권한이 있는 음원만 `images/bgm.mp3`로 올리고 `music.enabled: true`로 켜세요. 재생은 첫 터치 이후 시작되며 음악 버튼으로 끌 수 있습니다. 약도는 `images/map.jpg`로 올리고 `location.mapImage`에 경로를 넣습니다. 좌표가 없어도 네이버·카카오 장소 검색은 사용할 수 있어요.
