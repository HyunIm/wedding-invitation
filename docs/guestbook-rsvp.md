# 방명록·참석 응답을 구글 시트로 받기

기본 청첩장을 완성한 후 필요할 때 설정하세요. Google 계정 승인과 웹 앱 배포가 추가로 필요하며, 익숙하지 않으면 시간이 걸릴 수 있어요. 설정하지 않으면 두 기능은 하객에게 숨겨집니다.

## 1. 연결된 시트와 코드 준비

[sheets.new](https://sheets.new)에서 새 시트를 만들고 이름을 ‘청첩장 응답’으로 바꿉니다. **확장 프로그램 → Apps Script**에서 기존 코드를 지우고 [Code.gs](../google-apps-script/Code.gs) 전체를 붙여넣어 저장하세요. 시트에 연결된 편집기에서 시작해야 합니다.

코드의 `@OnlyCurrentDoc`는 현재 문서에 필요한 권한만 요청하도록 합니다. [Google 공식 권한 안내](https://developers.google.com/apps-script/guides/services/authorization)를 참고하세요. 실제 승인 화면에서 요청한 범위를 확인하고, 예상과 다르면 승인하지 말고 설정을 다시 확인하세요.

## 2. 웹 앱 배포

1. **배포 → 새 배포 → 톱니바퀴 → 웹 앱**을 선택하세요.
2. **실행: 나**, **액세스 권한: 모든 사용자**를 선택하세요. 하객이 로그인 없이 응답하도록 하는 설정입니다. 시트 자체를 ‘링크가 있는 모든 사용자’에게 공유할 필요는 없습니다.
3. 배포하고 자신의 계정으로 권한을 확인하세요. Google의 미확인 앱 안내가 나올 수 있습니다. 자신이 만든 프로젝트인지, 붙여넣은 코드와 권한이 예상대로인지 확인한 경우에만 진행하세요. 조직 계정 정책으로 막히면 관리자에게 확인하세요.
4. `/exec`로 끝나는 웹 앱 URL을 복사해 `config.js`의 `googleScriptUrl`에 넣으세요.

## 3. 실제 저장 확인

URL을 열어 정상 동작 메시지를 확인한 뒤, 청첩장에서 방명록과 참석 응답을 각각 한 번 제출하세요. 시트의 ‘방명록’, ‘참석여부’ 탭에 행이 생기는지 확인합니다. 테스트 행은 확인 후 삭제하세요. **URL 접속 성공만으로 응답 저장까지 확인한 것은 아닙니다.**

- 방명록은 이름·메시지·작성일이 청첩장에 공개됩니다. 전화번호 등 비공개 정보는 적지 않도록 화면에서도 안내합니다.
- 참석 응답은 주최자의 시트에 저장되고 공개 조회 API로 제공하지 않습니다. 응답 목적과 보관 기간을 정해 불필요해진 자료는 정리하세요.
- `askCompanion: false`이면 참석 응답 1건을 1명으로 집계합니다. 불참은 0명입니다. 인원은 서버에서도 1~20명 정수로 검사합니다.

## 운영과 제한

방명록의 ‘숨김’ 칸에 TRUE를 적으면 다음 조회부터 공개되지 않습니다. 행을 삭제해도 됩니다. 이미 열린 화면에는 새로고침 전까지 보일 수 있어요. 삭제 요청은 주최자가 직접 처리합니다.

서버는 한 번에 최대 50개 메시지를 반환하고 최대 200행만 검사합니다. 숨김 행이 많으면 ‘더보기’를 눌러야 이전 메시지가 보일 수 있어요. 동일 내용의 60초 내 반복 제출과 같은 요청 ID의 10분 내 재시도는 중복 행 생성을 줄입니다. 전체 제출은 분당 60건으로 제한합니다.

이 제한은 Google 캐시 기반의 **완화책**입니다. 공개 웹 앱에 대한 완전한 봇 차단이나 사용자 인증이 아니며 캐시 퇴거·서비스 할당량의 영향을 받습니다. 스팸이 계속되면 웹 앱 배포를 중지하고 CAPTCHA·인증을 지원하는 별도 폼을 고려하세요. 비밀 키를 공개 config.js에 넣는 것은 해결책이 아닙니다.

## 코드를 바꾼 뒤

**배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포**를 해야 반영됩니다. 같은 배포를 갱신하면 URL을 유지할 수 있습니다. 청첩장 코드를 업데이트했을 때 Apps Script도 함께 갱신하세요.
