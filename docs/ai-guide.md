# 비전공자와 청첩장을 만드는 AI 진행 안내

사용자는 GitHub와 코딩을 모를 수 있습니다. 한국어로 필요한 정보 3~4개만 질문하고, 한 번에 한 단계씩 완료 여부를 확인하세요. 이 저장소의 템플릿을 사용하며 다른 프레임워크로 새 사이트를 만들지 마세요.

1. README와 원본 config.js를 읽었는지 먼저 확인하세요. 링크를 읽지 못하면 docs/ai-start.txt 전체를 요청하세요. 원문을 보지 못한 상태에서 키 이름이나 구조를 추측하지 마세요.
2. 공개 저장소에서는 사진·연락처·계좌·설정 파일과 변경 이력이 공개된다는 점을 설명하세요. 화면에서 숨기는 기능은 비공개가 아닙니다. 사용자가 공개 범위를 확인한 뒤에만 privacy.publishConsent를 true로 설정하세요. 비밀번호·토큰·인증번호를 요청하지 마세요.
3. 필수: 신랑·신부 전체 이름, 예식 날짜, 한국시간, 예식장, 주소, 표지 사진. 선택: 부모님/관계/고인 여부, 연락처, 계좌, 인사말, 교통/식사 안내, 디자인. 모르는 선택 항목은 비우거나 끄세요. 날짜나 계좌를 추측하지 마세요.
4. firstName은 비워 전체 이름을 사용하세요. 이름만 따로 표시하고 싶다는 요청이 있을 때만 받으세요. meta.title과 meta.description도 기본은 빈 문자열로 두어 이름·날짜·장소에서 자동 생성하게 하세요. 회신 마감일은 사용자가 요청한 경우에만 넣고 예식일을 넘기지 마세요.
5. 계좌 배열은 실제 전달받은 계좌만 넣습니다. 예금주를 반드시 확인하세요. name을 비우면 role에 해당하는 인물의 이름을 사용합니다. 예: role이 '신랑 아버지'이면 groom.father.name을 사용합니다. 명의가 다르면 name을 직접 입력하세요.
6. lat/lng는 확실할 때만 숫자로 함께 넣습니다. 모르면 둘 다 ''로 둡니다. 이때 네이버·카카오 장소 검색으로 안내하며 티맵 버튼은 숨겨집니다.
7. 사진은 prepare.html에서 위치정보를 제거한 JPG 사본을 내려받아 올리게 안내하세요. HEIC는 사진 앱에서 JPG로 내보내야 하며 확장자 변경은 변환이 아닙니다. 원본을 공개 저장소에 올린 뒤 배포 최적화에 의존하지 마세요.
8. GitHub 아이디와 저장소 이름을 받아 README의 각 URL을 완성하세요. 기본은 웹 클릭/업로드/붙여넣기 방식입니다. 연결 도구를 쓸 수 있다면 실제 기능과 권한을 확인하세요. 도구 설치만으로 수정·배포 권한을 가진다고 가정하지 마세요.
9. 원본의 키·주석을 유지하고 값만 바꾸세요. 숨길 기능은 enabled:false, 계좌 목록은 []로 비울 수 있습니다. 사용자 입력의 따옴표·백틱을 올바르게 이스케이프하세요. 날짜 YYYY-MM-DD, 시간 HH:MM, 전화번호는 문자열, 불리언은 따옴표 없는 true/false입니다.
10. config.js 전체를 파일로 제공할 수 있으면 다운로드를 우선하고 전체 코드 블록도 주세요. 생략하지 마세요. 답이 잘렸다면 조각을 이어붙이게 하지 말고 완성된 파일을 다시 제공하세요. gallery.images는 []로 두고 표지는 images/cover.jpg입니다.
11. 이번 배포 결과를 확인하고 실패한 단계의 오류를 읽으세요. 모든 빨간 표시가 문법 오류라는 뜻은 아닙니다. 검사 통과 후에도 이름·시간·장소·사진·계좌·공유 미리보기를 확인하세요.
12. 기본 청첩장 완성 후에만 원하는 추가 기능을 안내하세요. 방명록/참석 응답은 Google Apps Script 배포, 카카오톡 버튼은 개발자 앱 설정이 필요합니다. 주소를 카톡에 붙여넣는 공유는 별도 앱 설정 없이 사용할 수 있습니다.

나중에 수정할 때는 사용 중인 최신 config.js를 먼저 읽으세요. 빈 시작 설정으로 기존 내용을 덮어쓰지 마세요. 수정한 값과 유지한 선택 항목을 설명하고, 공유 미리보기까지 다시 확인하세요.
